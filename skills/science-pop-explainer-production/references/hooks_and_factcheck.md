# 钩子公式库 · 认知张力叙事 · 事实核查清单 (Science Pop Explainer References)

> 配套 `skills/science-pop-explainer-production/SKILL.md` 使用的参考库。
> 适用场景: 知识科普类视频的开场钩子设计、叙事张力构建、发布前事实核查。

---

## 1. 钩子公式库 (Opening Hook Formulas)

前 3 秒决定完播率。五条经过验证的公式, 按选题性质选用:

### H1 反常识断言 (Contrarian Claim)
> "大家都知道 X, 但 X 的前提从来没人验证过。"

适用: 有广泛共识但缺乏审视的选题。风险: 断言必须有据, 否则塌房。

### H2 具象化尺度 (Scale Analogy)
> "如果把 X 放大/缩小到日常尺度, 它相当于……"

适用: 抽象系统/天文数字/微观结构。把 40 纳米/光速/百万并发翻译成生活经验。

### H3 身份代入 (Identity Projection)
> "你每天用的 X, 底层正在经历一场……"

适用: 日用品背后的原理 (微信消息/扫码支付/导航)。让观众成为当事人。

### H4 代价悬念 (Cost Suspense)
> "为了 X, 工程师付出了……代价。"

适用: 工程权衡/历史事故/失败案例。先亮代价, 再讲值不值。

### H5 时间压力 (Temporal Pressure)
> "这件事必须在 X 毫秒内完成, 否则……"

适用: 实时系统/金融交易/安全机制。用截止时间制造紧张。

**铁律**: 钩子承诺的内容, 正片必须兑现; 只钩不兑 = 标题党, 完播率与信任双输。

## 2. 认知张力叙事 (Cognitive Tension Narrative)

科普不是信息罗列, 是**张力的建立与释放**。三段式张力管理:

```
建立张力 (第1幕): 提出观众"以为自己懂"的问题 -> 揭示其认知缺口
维持张力 (第2-3幕): 逐层拆解, 每层结尾留一个新问题 (为什么这样设计? 代价是什么?)
释放张力 (第4-5幕): 完整因果闭环 + 可带走的思维模型 (一句话能复述的那种)
```

- 每幕结尾用"钩句"承接下一幕, 禁止"接下来我们看看……"式流水账过渡;
- 复杂概念先给"地图"再给"细节" (整体框架 -> 局部放大), 符合认知负荷理论;
- 数字必须锚定: 每个抽象数字配一个参照物 ("延迟降低 80% —— 相当于从 5 秒缩到 1 秒")。

## 3. 事实核查清单 (Fact-Check Checklist)

发布前逐项过; 任何一项存疑 -> 删改或标注, **不带着疑点发布**。

### 3.1 三类事实的核查标准
| 类型 | 标准 | 示例 |
|---|---|---|
| 可验证事实 | 至少一个权威信源 (官方文档/论文/一手数据) | 协议行为/API 语义/物理常数 |
| 工程判断 | 有实测或可复现依据; 无依据标注为"观点" | 性能对比/架构权衡 |
| 数字声明 | 原样引用 + 出处; 单位/量级/时间范围三对照 | "提升 80%" 须说明基线 |

### 3.2 三源核查 + 引用快照
- **三源核查**: 关键事实至少两个独立信源交叉验证; 冲突时取更保守表述或明示分歧;
- **引用快照**: 信源 URL + 访问日期存档 (热点内容截图/归档页), 防链接腐烂后无法自证;
- **时效标注**: 版本相关的结论注明适用版本 ("Python 3.12 起"), 避免过期误导。

### 3.3 LLM 辅助生成的特别规矩 (W5-6 起)
- LLM 草稿一律 `review.status=pending`, 经 `llm_scriptgen.py --approve` 批准才进生产;
- LLM 产出中的具体数字/引述默认存疑, 逐项核对后才可保留;
- 成片按平台规范附加 AI 生成标注 (`aiDisclosure` 块)。

### 3.4 签字项
- [ ] 全部可验证事实有信源且可访问
- [ ] 数字声明三对照 (单位/量级/时间范围) 通过
- [ ] 工程判断已标注依据或"观点"属性
- [ ] 关键信源已留快照 (URL + 访问日期)
- [ ] LLM 疑点逐项清除, 审校门已批准
